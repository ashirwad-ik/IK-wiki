# INV-1073 — Prompt migration (CareerOps → Langfuse) + tracing

- **Status:** scoped, not started. Plan prepared 2026-11-12, awaiting review + answers to open questions.
- **Jira:** https://uplevel-watch.atlassian.net/browse/INV-1073
- **Repo:** `career-ops/apps/backend/api` (Django + Celery)

## Goal

Wrap every OpenAI call in CareerOps with Langfuse tracing and move prompts into Langfuse Prompt Management.

## Out of scope

- Resume Analyzer (Aritra's — already on Langfuse; this ticket copies that pattern)
- CareerOps lead → Salesforce (n8n, no AI)
- Evals / quality scoring (separate later effort)

## 4 LLM touch-points to wrap

| # | Location | Does | Model |
|---|---|---|---|
| 1 | `resumes/services/profile_analysis.py` | Profile extraction + embeddings | `gpt-4.1-mini` |
| 2 | `resumes/services/resume_rewrite.py` | Resume rewrite (system + retry prompt) | `gpt-4.1-mini` |
| 3 | `resumes/services/resume_ocr.py` | OCR of image/PDF resumes | `gpt-4o` |
| 4 | `scraper/analysis/openai_client.py` | Job-matching signal extraction | env-configured |

Reusable: `pii_redact.py` (for Langfuse masking hook), `bq_sync.py` (`user_id` must match for reporting joins).

## Phases

0. **Setup** — `langfuse>=4.7,<5`, env vars, init at startup with PII masking + `release` = git SHA. Decision gate: same workspace as Resume Analyzer or separate (Q1).
1. **Tracing** — `@observe` on 4 entry points, spans for sub-steps, PII masking via `mask_otel_spans` + existing `redact_pii()`. Non-blocking/failure-tolerant.
2. **Prompt migration** — 4 prompts in Langfuse (`careerops/*`), fetched by label (`production`/`staging`). Cache TTL + prefetch so outage can't block deploys.
3. **Evals** — likely out of scope (Q5).
