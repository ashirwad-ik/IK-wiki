# INV-1073 — Prompt migration (CareerOps → Langfuse) + tracing

**Status:** scoped, not started. Plan + "understanding" artifacts prepared 2026-11-12, awaiting review by Aritra / EM and answers to open questions below before coding begins.

**Jira:** https://uplevel-watch.atlassian.net/browse/INV-1073
**Owner:** Ashirwad.
**Repo (in scope):** `career-ops/apps/backend/api` (Django + Celery). No other repo is touched.

## Goal (one line)

Wrap every OpenAI call in the CareerOps backend with Langfuse so each call is traced (success/failure, cost, latency, step-by-step), and move the prompts out of code into Langfuse so they are versioned and editable without a deploy.

## What this ticket does NOT touch

- **Resume Analyzer** (the 5 original lead magnets, AWS Lambdas). Aritra already added Langfuse there — it is the **reference implementation** this ticket copies, not something to change.
- **CareerOps lead → Salesforce path** (n8n). No AI call, out of scope.
- **Evals / pass-fail scoring** (datasets, LLM-as-judge). Separate later effort owned largely by product quality. Basic failure/cost/latency do come free from tracing; the quality-scoring layer does not.

## Where the OpenAI calls are today (what to wrap)

Four LLM touch-points, all using the OpenAI **Responses API** (`client.responses.parse(...)` with Pydantic structured output) and all with prompts hardcoded in Python:

| # | Code location | What it does | Entry point (= trace) | Model |
|---|---|---|---|---|
| 1 | `resumes/services/profile_analysis.py` | Extracts structured profile from resume (+ embeddings) | Celery `run_resume_analysis_task` → `analyze_resume_profile()` | `gpt-4.1-mini` |
| 2 | `resumes/services/resume_rewrite.py` | Rewrites resume for a job (`SYSTEM_PROMPT` + retry prompt) | Celery `generate_rewrite_task` → `generate_resume_rewrite()` | `gpt-4.1-mini` |
| 3 | `resumes/services/resume_ocr.py` | OCR of image/PDF resumes (`OCR_VISION_PROMPT`) | Called inside resume intake / analysis | `gpt-4o` |
| 4 | `scraper/analysis/openai_client.py` | Extracts job-matching signals from scraped postings (inline system prompt) | `analyze_jobs` scraper path | env `JOB_ANALYSIS_LLM_MODEL` |

**Already in the repo and reusable:**
- `resumes/services/pii_redact.py` — `redact_pii()` for email/phone/name. Reuse for the Langfuse masking hook; don't write new regex.
- `bq_sync.py` — BigQuery sync. `user_id` for Langfuse must match whatever this writes, so reporting joins work.

## Plan (in phases)

### Phase 0 — Setup (blocks everything)

- Add `langfuse>=4.7,<5` to backend requirements (SDK v4, pinned per Dipen's guide).
- Env vars: `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY`, `LANGFUSE_BASE_URL`, `LANGFUSE_TRACING_ENVIRONMENT` (development/staging/production), `LANGFUSE_SAMPLE_RATE`.
- Initialize Langfuse client once at Django app startup, with PII masking hook and `release` = git SHA.
- **Decision gate:** same Langfuse workspace as Resume Analyzer (tagged `source:careerops`) or separate — see Q1.

### Phase 1 — Tracing (the real blocker; unlocks cost/latency/failure views)

- Wrap each of the 4 entry points as a **trace** (`@observe`); inside, meaningful steps as **spans** (OCR, embedding) and OpenAI calls as **generations**.
- On each trace set: `source:careerops` tag, `user_id` = internal lead id, `session_id` for multi-step flows, model params as metadata.
- Wire **PII masking** via `mask_otel_spans`, built on existing `redact_pii()`. Verify on real traces.
- All Langfuse calls **non-blocking / failure-tolerant** — if Langfuse is down, user requests still succeed.

### Phase 2 — Prompt migration (the ticket title)

- Create 4 prompts in Langfuse Prompt Management under `careerops/` namespace. v1 → `production` label, v2 → `staging` label.
- Replace hardcoded strings with `get_prompt("careerops/...", label=...)`, pass the prompt object into the generation so prompt metrics populate.
- Sensible cache TTL + prefetch at startup so a Langfuse outage can't block deploys.

Prompt mapping:

| Code string today | Langfuse prompt name | Trace name |
|---|---|---|
| `profile_analysis.py` system prompt | `careerops/profile_extraction` | `resume_profile_analysis` |
| `resume_rewrite.py` `SYSTEM_PROMPT` (+retry) | `careerops/resume_rewrite` | `resume_rewrite` |
| `resume_ocr.py` `OCR_VISION_PROMPT` | `careerops/ocr_vision` | span inside analysis |
| `openai_client.py` inline system prompt | `careerops/job_analysis_extraction` | `job_analysis` |

### Phase 3 — Evals (likely out of scope for INV-1073)

Datasets, human scoring, LLM-as-judge, pass/fail gates. Mostly a Langfuse-UI effort owned by product quality, done after traces flow. Confirm scope with EM (Q5).

## Definition of Done (from Dipen's guide, trimmed to this ticket)

- [ ] A trace in Langfuse for every resume-analysis and rewrite request (1 request = 1 trace).
- [ ] Sub-steps are spans; OpenAI calls are generations with token counts and non-zero cost.
- [ ] No unredacted PII (name/email/phone) on real traces, verified.
- [ ] Each trace labelled with `source:careerops` and the internal user/lead id, matching existing reporting (BigQuery).
- [ ] All 4 prompts fetched from Langfuse by label; no prompt strings left in code.
- [ ] Langfuse outage never breaks or slows a user request.
- [ ] Cost + latency dashboard exists for `source:careerops`.

## Key technical choices

| Choice | What it means |
|---|---|
| Tag vs metadata | `source:careerops` is a **tag** (filter dashboards). Temperature, page-count etc. are **metadata** (single-trace detail). Never put a user id in a tag. |
| Fetch prompts by **label**, not version | Code asks for the `production` (or `staging`) prompt. Ship a new version = move the label in UI. Rollback = move it back. No deploy. |
| `user_id` = internal lead id | Never email/phone. Must match the id BigQuery / reporting uses so numbers join. |
| Masking before export | Resume text is PII-heavy. Scrub in-process before Langfuse sees anything, via `mask_otel_spans` so OpenAI-wrapper spans are also covered. |
| Observability never breaks the app | Langfuse unreachable → lose visibility, never the user's result. |
