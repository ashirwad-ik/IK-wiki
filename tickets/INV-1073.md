## Decisions settled (so we don't re-derive them)

- **One Langfuse project `CareerOps`.** Not one per env. `LANGFUSE_TRACING_ENVIRONMENT` + prompt labels do the env split.
- **OpenAI wrapper:** use `langfuse.openai.OpenAI` drop-in (no custom wrapper). Needs `openai>=1.66.0` so Responses API (`responses.parse`) is captured. Confirmed by Aritra.
- **user_id:** `CandidateProfile.id` via `analysis.session.candidate_session.candidate_id`. `None` before unlock. Never email/phone/request UUID/analysis_id.
- **session_id:** `analysis.session_id`.
- **source tag:** `source:career-ops` (matches the BQ `data_source` string).
- **Employer redaction:** currently OUT (matches `pii_redact.py`). Revisit if data-policy decision changes on Resume Analyzer side.
- **Media upload:** `LANGFUSE_MEDIA_UPLOAD_ENABLED=false` — required for the mask to actually fire on OCR calls.
- **Env:** `LANGFUSE_TRACING_ENVIRONMENT=staging` on QA, `production` on prod. Repo's own `ENVIRONMENT=qa` is a different variable.

## Open — still blocking traces on staging

- **SSM → ECS task-def mapping.** The 6 `/career-ops/stg/LANGFUSE_*` params exist in SSM, but the task definition's `secrets:` block needs to list them so they inject as env vars at container boot. Without that, `configure_langfuse()` hits the "no key → no-op" branch and zero traces reach Langfuse. Manager-side action.

6. Shadow-run on staging — upload resume, byte-diff OpenAI input against pre-migration.
