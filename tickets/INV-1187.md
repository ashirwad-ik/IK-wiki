## Architecture — how tiers are decided (post-redesign)

- **Hint click** → dock button opens the **picker card**. Three tiles: Nudge / Approach / Walkthrough. Each shows a one-line subtitle + the exact per-module score impact. Walkthrough tile hidden for Behavioural + unknown modules.
- **Candidate picks a tile** → FE sends `{force_tier}` in the RPC payload. Worker always requires `force_tier` — missing → typed error (`missing_tier`). No LLM tier selection anywhere.
- **Picker tier availability + penalty copy** is driven by `useGetInterviewStatusApi.interview_round` (DSA / ML / BACKEND_ENGINEERING / BEHAVIOURAL), **not** the worker's per-question module. A DSA round that opens with a behavioural warm-up still shows DSA penalties — consistent across every question in the round.
- **Behavioural (incl. Leadership, BEHAVIOURAL_MULTITOPIC)** → never serves Walkthrough. Defended at three layers (the worker `decide_tier` layer is gone — no tier picker on the worker any more):
  1. Worker RPC response canonicalises module string (`BEHAVIOURAL_MULTITOPIC` → `BEHAVIOURAL`, empty → `BEHAVIOURAL`)
  2. Worker handler downgrades `WALKTHROUGH + behavioural` → `APPROACH` before persisting
  3. FE hides the Walkthrough tile entirely for non-whitelisted modules
- **Malformed LLM JSON** → worker regex-salvages; if unsalvageable, serves a safe generic hint. FE mirrors the salvage as a last line of defence. Raw JSON can never reach the candidate's card.
- **Back button** on the result card returns to the picker. **Dock Hint button** always opens / returns to the picker — never closes the card. **"Got it"** is the only dismiss.

## Contract

- **LiveKit RPC**: method `request_hint`. Payload **always** `{force_tier: "NUDGE" | "APPROACH" | "WALKTHROUGH"}` — missing → `{error: "missing_tier"}`, LLM failure → `{error: "generation_failed"}`. Response: JSON string `{tier, text, hint_id, question_index, module}`. Module is canonicalised server-side.
- **BE record endpoint**: `POST /api/v1/ai_mock_interview/interview/{id}/hint`, guarded by `X-Internal-Api-Key`, idempotent on `(interview_id, hint_id)`, 422 on Behavioural + WALKTHROUGH.
- **BE summary**: `GET /api/v1/ai_mock_interview/interview/{id}/hints/summary`.
- **Main report payload** carries `hints_used`, `hints_breakdown`, plus `hints_penalties` (per-category dict), `hints_total_penalty` (sum), and per-entry `hint_penalty` on each adjusted `domain_specific_feedback` / `summary` entry. Legacy interviews with no hints get an early-return — response identical to before.
- **Table**: `ai_mock_interview_hints (id, interview_id, sub, question_index, tier ENUM, hint_id UNIQUE on (interview_id, hint_id), text TEXT, served_at, created_at)` — migration `017_add_interview_hints_table` in BE PR #59.
- **Score application**: `student_report_service._apply_hint_penalties` subtracts per-category deltas from matching `domain_specific_feedback[].domain` entries and sums into `summary.score`. Every write is `max(0, round(score + delta, 2))` — scores never go negative. Zero-hint interviews short-circuit.
