## Architecture — how tiers are decided

- **Regular Hint click** → worker passes full context (module, question, code buffer, transcript tail, prior hints, which button was pressed) to the LLM; LLM returns strict JSON `{tier, text}`.
- **Still stuck → Approach / Walkthrough** → FE sends `{force_tier}` payload; worker honours it verbatim, LLM's tier field ignored.
- **Behavioural (incl. Leadership, BEHAVIOURAL_MULTITOPIC)** → never serves Walkthrough. Defended at four layers:
  1. Worker `decide_tier` uses whitelist (`DSA`, `DSA_MULTITOPIC`, `ML`, `BACKEND_ENGINEERING`)
  2. Worker RPC response canonicalises module string
  3. FE `nextTierAfter` uses same whitelist
  4. FE hook clamps `WALKTHROUGH + non-whitelisted module` → `APPROACH` before card renders
- **Malformed LLM JSON** → worker regex-salvages; if unsalvageable, serves a safe generic hint. FE mirrors the salvage as a last line of defence. Raw JSON can never reach the candidate's card.

## Contract

- **LiveKit RPC**: method `request_hint`. Payload is `{}` (agent picks) or `{force_tier: "NUDGE" | "APPROACH" | "WALKTHROUGH"}` (user forces). Response: JSON string `{tier, text, hint_id, question_index, module}`. Module is canonicalised server-side.
- **BE record endpoint**: `POST /api/v1/ai_mock_interview/interview/{id}/hint`, guarded by `X-Internal-Api-Key`, idempotent on `(interview_id, hint_id)`, 422 on Behavioural + WALKTHROUGH.
- **BE summary**: `GET /api/v1/ai_mock_interview/interview/{id}/hints/summary`.
- **Main report payload** carries `hints_used` + `hints_breakdown`; legacy interviews return `0` / `[]`.
- **Table**: `ai_mock_interview_hints (id, interview_id, sub, question_index, tier ENUM, hint_id UNIQUE on (interview_id, hint_id), text TEXT, served_at, created_at)`.
